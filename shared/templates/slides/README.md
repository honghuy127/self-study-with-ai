# Slide deck design principles

Distilled from a real deck project in which a dense Madrid draft and a
PowerPoint conversion were both rejected, then rebuilt into the accepted
design. Apply these principles when finalizing any slides deliverable. The
scaffold `main.tex` in this directory stays minimal on purpose; the writer
upgrades it during drafting.

## 1. Format

- **LaTeX beamer is the canonical, reproducible route.** Build with
  `python3 tools/build.py slides <study-dir>` (latexmk, pdflatex). Sources stay in
  git; the PDF lives in `slides/build/` and is regenerated, never edited by
  hand.
- **PowerPoint is not rejected as a format; it is blocked only by the lack
  of a good template.** A `.pptx` conversion was once built from a Fake
  Beamer template and rejected because the template looked bad, not because
  PowerPoint is inherently out of scope. The rule:
  until a template the human accepts exists in the repo, generate beamer
  PDFs. If a PowerPoint deliverable is requested again, first ask the human
  whether an acceptable template is available; if not, say so and build the
  beamer version.
- 16:9: `\documentclass[aspectratio=169,10pt]{beamer}`.
- Bibliography: generated by `python3 tools/gen_bib.py <study-dir>` into
  `slides/refs.bib`; cite with natbib numbers.

## 2. Visual design

- **Theme: metropolis**, `\usetheme[progressbar=frametitle,block=fill]{metropolis}`
  (bundled in TeX Live; no extra packages needed with pdflatex).
- One `\section` per paper or major part; metropolis renders standout
  divider slides for free. Accept that PDF pages exceed content frames.
- **Density limits** (the lesson of the rejected v1):
  - max 5 top-level bullets per frame; one idea per frame;
  - split a paper's problem/method/results/limitations across multiple
    frames;
  - one table per results frame, `\small` or `\footnotesize` booktabs;
  - transpose wide comparison tables (dimensions as rows, papers as
    columns) instead of shrinking them;
  - use `alertblock` or `exampleblock` sparingly for callouts (for example
    an internal inconsistency in a paper).
- **No on-slide locator footers.** Claim-to-source mapping lives in
  `slides/deck-plan.md` (storyboard), not on the slides.
- **Show what you cite.** If a frame's content depends on a paper equation
  or algorithm, display the equation or algorithm step inline on that
  frame, keeping the paper's own symbols and equation numbering (for
  example `\tag{4}`). References to figures and tables may stay
  locator-only when the artifact itself is not reproduced, but never cite
  an equation a slide is built around without showing it. Equations are
  reconstructed from the full-text snapshot and the approved notes, never
  from memory.

## 3. Text style

- Frame titles in **title case**: capitalize each word except small words
  (a, an, and, as, at, by, for, in, of, on, or, the, to, under, via, vs,
  with); keep acronyms and proper nouns (TBOP, XSTest, LLaVA) untouched.
- **Name papers by short name**, never positionally: `TBOP: Key Results`,
  not `Paper 2: Key Results`. Use the paper's own method name or acronym;
  overview frames state the full title and authors (affiliations verified
  against the snapshot).
- American English; compact declarative voice; no em-dashes; citations tied
  with `~`; one space around `&` in tables, no padding around `\\`.
- All numbers character-exact from the approved notes; unverifiable figures
  are omitted or explicitly flagged, never asserted.

## 4. Verification (talk gate)

1. `python3 tools/gen_bib.py <study-dir>`
2. `python3 tools/build.py slides <study-dir>`
3. `python3 tools/lint_report.py <study-dir>` (must exit clean)
4. `pdftoppm -png -r 70 slides/build/main.pdf <dir>/s`, visually inspect
   every page for overflow, clipping, contrast, and number consistency;
   grep the log for `Overfull \hbox/\vbox`. Only appearance-verified benign
   overflows may ride.
5. Human approval of the draft gate (delegated) or deck gate
   (paper-reading) before the review stage.

## History (why these rules exist)

- v1, Madrid, 38 frames: rejected as too dense.
- v1.5, PowerPoint from a Fake Beamer template: rejected; the template and
  the whole `shared/templates/powerpoint/` directory were removed from the
  repo.
- v2/v3/v4, metropolis at 72 frames + 7 dividers, no locator footers,
  title-case short-name titles: accepted design; this document.
