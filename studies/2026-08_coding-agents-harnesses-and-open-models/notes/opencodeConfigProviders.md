## Purpose and role in the harness

This component assembles the runtime configuration for an OpenCode instance and turns it into usable model providers. The `Config` service (`@opencode/Config`) loads, validates, and merges every config layer into one `Info` object per project instance (`packages/opencode/src/config/config.ts:124-135`, `packages/opencode/src/config/config.ts:600-608`). The `Provider` service (`@opencode/Provider`) merges a fetched model catalog, environment variables, stored credentials, config-declared providers, and plugin hooks into an active provider registry, then resolves Vercel AI SDK `LanguageModelV3` instances on demand (`packages/opencode/src/provider/provider.ts:1165-1189`). The `Auth` service persists per-provider credentials in a single JSON file (`packages/opencode/src/auth/index.ts:10`). Config is cached per instance directory through `InstanceState` (`packages/opencode/src/config/config.ts:600-608`, `packages/opencode/src/effect/instance-state.ts:26-52`), so each opened project directory gets its own merged configuration.

## Mechanism

### Config discovery and precedence

Loading is one ordered pipeline in `loadInstanceState` (`packages/opencode/src/config/config.ts:314-596`). Each layer is deep-merged over the previous one with remeda's `mergeDeep` (`packages/opencode/src/config/config.ts:41-43`), so the last merged source wins; `instructions` arrays are unioned and deduplicated instead of replaced (`packages/opencode/src/config/config.ts:45-51`). Order, lowest to highest precedence:

1. Remote configs tied to `wellknown` auth entries: for each auth entry of type `wellknown`, fetch `${url}/.well-known/opencode`, decode against `ConfigV1.WellKnown`, optionally fetch the `remote_config.url` it points to (merging its `config` object), then merge the result with scope `"global"` (`packages/opencode/src/config/config.ts:356-396`). The stored token is exported into a private `authEnv` record under the wellknown's `key` and used for variable substitution in the remote fetch and in all subsequent file loads (`packages/opencode/src/config/config.ts:319`, `packages/opencode/src/config/config.ts:359`, `packages/opencode/src/config/config.ts:398`).
2. Global config directory: `$XDG_CONFIG_HOME/opencode` (`packages/core/src/global.ts:13`), reading `config.json`, then `opencode.json`, then `opencode.jsonc`, later files winning (`packages/opencode/src/config/config.ts:258-260`). A missing file on this path is seeded with `{"$schema": "https://opencode.ai/config.json"}` unless `OPENCODE_CONFIG`, `OPENCODE_CONFIG_DIR`, or `OPENCODE_CONFIG_CONTENT` is set (`packages/opencode/src/config/config.ts:250-257`). A legacy TOML file at `config.json`-sibling path `config` is imported (`{ with: { type: "toml" } }`), converted (`provider` + `model` become `model: "${provider}/${model}"`), written back as `config.json`, and deleted (`packages/opencode/src/config/config.ts:262-276`). The global result is cached with infinite TTL until `invalidate` (`packages/opencode/src/config/config.ts:281-293`).
3. Explicit custom file from `OPENCODE_CONFIG` (`packages/opencode/src/config/config.ts:401-404`) (`packages/core/src/flag/flag.ts:21`).
4. Project files: `opencode.jsonc` / `opencode.json` found by walking up from `ctx.directory` to `ctx.worktree` (`packages/opencode/src/config/paths.ts:10-21` using the `up` walker at `packages/core/src/fs-util.ts:168-182`), reversed so the file nearest the working directory merges last and wins (`packages/opencode/src/config/paths.ts:20`). Skipped when `OPENCODE_DISABLE_PROJECT_CONFIG` is truthy (`packages/opencode/src/config/config.ts:406-410`). These merges are tagged scope `"local"` for plugin provenance (`packages/opencode/src/config/config.ts:408`).
5. Config directories loop over `ConfigPaths.directories`: `[Global.Path.config, ...cwd-up-to-worktree ".opencode" dirs, ~/.opencode, OPENCODE_CONFIG_DIR]`, deduplicated in that order (`packages/opencode/src/config/paths.ts:23-41`). A directory contributes its `opencode.json`/`opencode.jsonc` only when it ends with `.opencode` or equals `OPENCODE_CONFIG_DIR` (`packages/opencode/src/config/config.ts:424-434`). Because the array is not reversed, among `.opencode` directories the entry farther from the working directory (and `~/.opencode`, and `OPENCODE_CONFIG_DIR`) overrides the closer one. Every directory in the loop additionally gets: a generated `.gitignore` with contents `node_modules`, `package.json`, `package-lock.json`, `bun.lock`, `.gitignore` (`packages/opencode/src/config/config.ts:295-312`, `packages/opencode/src/config/config.ts:436`); a detached background npm install of `@opencode-ai/plugin` pinned to `InstallationVersion` unless running from a local installation (`packages/opencode/src/config/config.ts:438-457`); markdown-defined commands from `{command,commands}/**/*.md` (`packages/opencode/src/config/config.ts:459`, `packages/opencode/src/config/command.ts:13-39`); agents from `{agent,agents}/**/*.md` and modes from `{mode,modes}/*.md` (`packages/opencode/src/config/config.ts:460-461`, `packages/opencode/src/config/agent.ts:11-59`); and auto-discovered plugins from `{plugin,plugins}/*.{ts,js}` (`packages/opencode/src/config/config.ts:462-465`, `packages/opencode/src/config/plugin.ts:18-30`).
6. Inline config from `process.env.OPENCODE_CONFIG_CONTENT`, parsed as virtual source `"OPENCODE_CONFIG_CONTENT"` with scope `"local"` (`packages/opencode/src/config/config.ts:468-476`).
7. Console/org remote config: if an active account has `active_org_id`, its token is exported as `OPENCODE_CONSOLE_TOKEN` into both `process.env` and the `Env` service, and the org config fetched via `accountSvc.config` is merged with scope `"global"`; its provider IDs are recorded as `consoleManagedProviders` (`packages/opencode/src/config/config.ts:478-514`, `packages/opencode/src/config/config.ts:590-594`).
8. OS-managed directory from `managedConfigDir()`: `/Library/Application Support/opencode` on darwin, `%ProgramData%\opencode` on win32, `/etc/opencode` otherwise (`packages/opencode/src/config/managed.ts:20-29`), loading `opencode.json`/`opencode.jsonc` with scope `"global"` (`packages/opencode/src/config/config.ts:516-522`).
9. macOS MDM managed preferences: the plist `ai.opencode.managed` found at `/Library/Managed Preferences/<user>/` or `/Library/Managed Preferences/`, converted with `plutil -convert json -o -`, with `Payload*` meta keys stripped, merged last; the code comment reads "macOS managed preferences (.mobileconfig deployed via MDM) override everything" (`packages/opencode/src/config/config.ts:524-534`, `packages/opencode/src/config/managed.ts:8-18`, `packages/opencode/src/config/managed.ts:43-69`).

Post-processing then: converts each `mode` entry into an agent with `mode: "primary"` (`packages/opencode/src/config/config.ts:536-543`); deep-merges JSON from `OPENCODE_PERMISSION` into `permission`, warning on invalid JSON (`packages/opencode/src/config/config.ts:545-551`); translates the legacy boolean `tools` map into permission `allow`/`deny` entries, collapsing `write`, `edit`, and `patch` into a single `edit` permission (`packages/opencode/src/config/config.ts:553-564`); defaults `username` to `os.userInfo().username` with fallback `"user"` (`packages/opencode/src/config/config.ts:566-573`); maps `autoshare: true` to `share: "auto"` (`packages/opencode/src/config/config.ts:575-577`); and forces `compaction.auto = false` / `compaction.prune = false` under `OPENCODE_DISABLE_AUTOCOMPACT` / `OPENCODE_DISABLE_PRUNE` (`packages/opencode/src/config/config.ts:579-584`).

### File parsing

Raw file text first passes variable substitution (`packages/opencode/src/config/config.ts:219-226`), then JSONC parsing via `jsonc-parser` with `allowTrailingComma: true` and detailed line/column error reporting (`packages/opencode/src/config/parse.ts:8-33`), then Effect-Schema decoding of `ConfigV1.Info` with `errors: "all"`, `onExcessProperty: "ignore"`, `propertyOrder: "original"` (`packages/opencode/src/config/parse.ts:35-61`). Unknown keys are silently dropped by `onExcessProperty: "ignore"`. `normalizeLoadedConfig` strips legacy top-level keys `theme`, `keybinds`, `tui` before schema decoding (`packages/opencode/src/config/config.ts:53-62`). For file-based sources missing `$schema`, the loader injects `"$schema": "https://opencode.ai/config.json"` and writes the file back (`packages/opencode/src/config/config.ts:231-235`). Variable substitution supports `{env:VAR}` and `{file:path}`: env lookups fall back to `""` silently (`packages/opencode/src/config/variable.ts:36-38`); file references expand `~/`, resolve relative to the config file's directory, trim and JSON-escape the content, raise `InvalidError` on missing files unless `missing: "empty"`, and skip tokens on `//` comment lines (`packages/opencode/src/config/variable.ts:40-90`).

Plugin specs that look like paths are resolved to `file://` URLs relative to the declaring config file at load time, so later merges cannot reinterpret `./plugin.ts` (`packages/opencode/src/config/config.ts:101-109`, `packages/opencode/src/config/plugin.ts:40-60`). Plugin origins are deduplicated by identity (npm package name or exact file URL); because `deduplicatePluginOrigins` iterates the merged list from the end, the last-merged occurrence of a plugin wins (`packages/opencode/src/config/plugin.ts:62-77`). Scope is inferred per source: http(s) sources are `"global"`, `OPENCODE_CONFIG_CONTENT` is `"local"`, sources inside the project (`containsPath` against `ctx.directory` or `ctx.worktree`) are `"local"`, otherwise `"global"` (`packages/opencode/src/config/config.ts:323-328`, `packages/opencode/src/project/instance-context.ts:18-24`).

Writes go through `Config.update` (merges into `config.json` in the instance directory, `packages/opencode/src/config/config.ts:624-631`) and `Config.updateGlobal` (patches the first existing of `opencode.jsonc`, `opencode.json`, `config.json` in the global config dir; `.jsonc` files are edited in place via `jsonc-parser` `modify`/`applyEdits`, other files are re-serialized; changes invalidate the global cache) (`packages/opencode/src/config/config.ts:139-147`, `packages/opencode/src/config/config.ts:149-161`, `packages/opencode/src/config/config.ts:637-660`).

### Config schema

The top-level schema is `ConfigV1.Info` (`packages/core/src/v1/config/config.ts:32-190`), annotated per field. Notable fields: `$schema`, `shell`, `logLevel` (`DEBUG`/`INFO`/`WARN`/`ERROR`), `server`, `command`, `skills`, `references` plus deprecated `reference`, `watcher.ignore`, `snapshot`, `plugin`, `share` (`manual`/`auto`/`disabled`), deprecated `autoshare`, `autoupdate` (boolean or `"notify"`), `disabled_providers`, `enabled_providers`, `model` ("Model to use in the format of provider/model, eg anthropic/claude-2"), `small_model`, `default_agent`, `subagent_depth`, `username`, deprecated `mode`, `agent` (known keys `plan`, `build`, `general`, `explore`, `title`, `summary`, `compaction` plus arbitrary extras), `provider`, `mcp`, `formatter`, `lsp`, `instructions`, deprecated `layout`, `permission`, `tools`, `attachment`, `enterprise.url`, `tool_output.max_lines`/`max_bytes`, `compaction` (`auto`, `prune`, `tail_turns`, `preserve_recent_tokens`, `reserved`), `experimental` (`disable_paste_summary`, `batch_tool`, `openTelemetry`, `primary_tools`, `continue_loop_on_deny`, `mcp_timeout`, `policies`). Defaults stated in schema descriptions: `snapshot` "Defaults to true", `subagent_depth` "Defaults to 1", `tool_output.max_lines` "default: 2000", `tool_output.max_bytes` "default: 51200", `compaction.auto` "default: true", `compaction.prune` "default: false" (`packages/core/src/v1/config/config.ts:52-167`); the enforcing code for these defaults lives outside this component.

The provider sub-schema `ConfigProviderV1.Info` has `api`, `name`, `env` (string array), `id`, `npm`, `whitelist`, `blacklist`, `options` (typed keys `apiKey`, `baseURL`, `enterpriseUrl`, `setCacheKey`, `timeout`, `headerTimeout`, `chunkTimeout`, open to arbitrary additional keys via `Schema.StructWithRest`), and `models` (`packages/core/src/v1/config/provider.ts:82-126`). Model entries carry `id`, `name`, `family`, `release_date`, capability booleans (`attachment`, `reasoning`, `temperature`, `tool_call`), `interleaved`, `cost` (with `cache_read`/`cache_write`/`context_over_200k`), `limit` (`context`, `input`, `output`), `modalities`, `experimental`, `status` (`alpha`/`beta`/`deprecated`/`active`), `provider.npm`/`provider.api`, `options`, `headers`, and `variants` with a `disabled` flag (`packages/core/src/v1/config/provider.ts:6-80`).

### Provider registry assembly

The provider state machine (Provider service layer, `packages/opencode/src/provider/provider.ts:1359-2015`) layers sources in a fixed order:

1. Catalog: the `ModelsDev` service supplies a provider/model catalog. Despite the name, the pinned tree fetches from `https://models.opencode.ai` (override `OPENCODE_MODELS_URL`), requesting `${source}/api.json` with User-Agent `opencode/${InstallationChannel}/${InstallationVersion}/${Flag.OPENCODE_CLIENT}` and a 10 second timeout (`packages/core/src/models-dev.ts:23`, `packages/core/src/models-dev.ts:160`, `packages/core/src/models-dev.ts:175-182`). The cache file is `models.json` in `Global.Path.cache` (`models-<hash>.json` for non-default sources) with a 5 minute freshness TTL, a cross-process `Flock` guarding fetch-and-write, and a scheduled refresh every 60 minutes (`packages/core/src/models-dev.ts:160-167`, `packages/core/src/models-dev.ts:202-231`, `packages/core/src/models-dev.ts:255-258`). Populate order: disk cache, then bundled snapshot global `OPENCODE_MODELS_DEV` if compiled in, then fetch; `OPENCODE_DISABLE_MODELS_FETCH` short-circuits to `{}` (`packages/core/src/models-dev.ts:136-137`, `packages/core/src/models-dev.ts:217-231`).
2. Catalog conversion: every catalog provider becomes an `Info` with `source: "custom"` via `fromModelsDevProvider`; SDK package resolution order is the Cloudflare-gateway special case, `model.provider.npm`, `provider.npm`, fallback `"@ai-sdk/openai-compatible"`; `status` defaults to `"active"`, `toolcall` to true; `experimental.modes` entries become extra models named `${model.id}-${mode}` (`packages/opencode/src/provider/provider.ts:1235-1317`).
3. Plugin model hooks run first ("load plugins first so config() hook runs before reading cfg.provider"): each plugin's `provider.models` hook can rewrite a provider's model list, receiving the provider's public info plus its stored auth (`packages/opencode/src/provider/provider.ts:1410-1449`).
4. Config extension: each `config.provider` entry is merged over the catalog entry with `source: "config"`, filling per-model defaults (capability defaults `temperature`/`reasoning`/`attachment` false, `tool_call` true, input/output `text` true; cost fields default 0; deepseek-compatible models default `interleaved: { field: "reasoning_content" }`) (`packages/opencode/src/provider/provider.ts:1451-1550`).
5. Environment activation: for every catalog provider, if any name in its `env` array is set, the provider is activated with `source: "env"`, and `key` is the env value only when the provider declares exactly one env var (`packages/opencode/src/provider/provider.ts:1552-1563`).
6. Stored credentials: `auth.json` entries of type `api` activate providers with `source: "api"` and `key` (`packages/opencode/src/provider/provider.ts:1565-1576`).
7. Plugin auth loaders: plugins exporting `auth.loader` contribute SDK options for their provider (`packages/opencode/src/provider/provider.ts:1578-1597`).
8. Built-in `custom()` per-provider integrations (23 entries: `anthropic`, `opencode`, `openai`, `meta`, `xai`, `github-copilot`, `azure`, `azure-cognitive-services`, `amazon-bedrock`, `llmgateway`, `openrouter`, `nvidia`, `vercel`, `google-vertex`, `google-vertex-anthropic`, `sap-ai-core`, `zenmux`, `gitlab`, `cloudflare-workers-ai`, `cloudflare-ai-gateway`, `cerebras`, `kilo`, `snowflake-cortex`, `packages/opencode/src/provider/provider.ts:168-975`): a loader returns `autoload` plus SDK options, a `getModel` selector, `vars` for baseURL templating, and optionally `discoverModels` (`packages/opencode/src/provider/provider.ts:136-145`); it applies when `autoload` is true or the provider is already active (`packages/opencode/src/provider/provider.ts:1599-1615`).
9. Config re-application: config-declared providers are force-activated last (`source: "config"`) so merely listing a provider in config makes it active without any credential (`packages/opencode/src/provider/provider.ts:1617-1625`).
10. Filtering: `enabled_providers` (whitelist, "ONLY these providers will be enabled") and `disabled_providers` remove providers; `gpt-5-chat-latest` aliases are deleted for `openai`/`github-copilot`/`openrouter` (and `openai/gpt-5-chat` on openrouter); `alpha` models are dropped unless `runtimeFlags.enableExperimentalModels`; `deprecated` models are dropped; per-provider `whitelist`/`blacklist` filter models; providers left with zero models are deleted (`packages/opencode/src/provider/provider.ts:1641-1689`).

`mergeProvider` seeds an inactive provider from the catalog before deep-merging the patch (`packages/opencode/src/provider/provider.ts:1397-1408`). GitLab additionally runs a workflow-model discovery pass against the instance URL (`packages/opencode/src/provider/provider.ts:1627-1639`, `packages/opencode/src/provider/provider.ts:661-726`).

SDK resolution (`resolveSDK`): `baseURL` is `options.baseURL ?? model.api.url`, then `${KEY}` placeholders are replaced by the provider's `vars` loader and then by the environment (`packages/opencode/src/provider/provider.ts:1729-1750`); `apiKey` falls back to the provider's `key` (`packages/opencode/src/provider/provider.ts:1751`); OpenAI-compatible SDKs get `includeUsage: true` unless explicitly disabled (`packages/opencode/src/provider/provider.ts:1725-1727`). The fetch wrapper combines abort signals and implements `headerTimeout` (abort while waiting for headers) and `chunkTimeout` (per-SSE-chunk read timeout via `wrapSSE`) (`packages/opencode/src/provider/provider.ts:1768-1799`, `packages/opencode/src/provider/provider.ts:37-92`). Bundled SDKs are dynamically imported from 24 pre-declared npm packages in `BUNDLED_PROVIDERS` (`packages/opencode/src/provider/provider.ts:107-134`); any other `model.api.npm` value (including `file://` local paths) is installed through `Npm.add` at runtime and loaded by picking the first export whose name starts with `create` (`packages/opencode/src/provider/provider.ts:1812-1830`). Instantiated SDKs are cached under a hash of `{providerID, npm, options}` (`packages/opencode/src/provider/provider.ts:1758-1766`).

Model selection: `parseModel` splits a `provider/model` string on the first `/` (`packages/opencode/src/provider/provider.ts:2028-2034`). `defaultModel` resolution order: `config.model`, then the most recent still-available entry from `model.json` in `Global.Path.state` (`recent[]` array), then the first available provider preferring one declared in `config.provider`, then its best model under `sort()` whose priority list is `["gpt-5", "claude-sonnet-4", "big-pickle", "gemini-3-pro"]`, preferring IDs without `"latest"` and breaking ties descending (`packages/opencode/src/provider/provider.ts:1978-2011`, `packages/opencode/src/provider/provider.ts:2017-2026`). `getSmallModel` order: `config.small_model`, then the `experimental.provider.small_model` plugin hook, then family priority `["gemini-flash", "gpt-nano", "claude-haiku"]` (opencode-prefixed providers use `["gpt-nano"]`, github-copilot uses `["gpt-mini", ...]`); azure returns undefined (`packages/opencode/src/provider/provider.ts:1909-1976`, `packages/opencode/src/provider/provider.ts:2018`). Model lookup failures raise `ProviderModelNotFoundError` with fuzzysort-based suggestions (`packages/opencode/src/provider/provider.ts:1111-1125`, `packages/opencode/src/provider/provider.ts:1330-1357`, `packages/opencode/src/provider/provider.ts:1842-1863`).

Transform layer (`packages/opencode/src/provider/transform.ts`): `message()` rewrites message history per provider before each request, including Anthropic/Bedrock empty-content filtering (`transform.ts:168-223`), Claude `toolCallId` scrubbing to `[a-zA-Z0-9_-]` (`transform.ts:225-252`), Mistral ID scrubbing to 9 alphanumeric chars plus a synthetic `Done.` assistant turn after tool messages (`transform.ts:254-302`), DeepSeek forced reasoning parts (`transform.ts:304-320`), and interleaved-reasoning field round-tripping (`transform.ts:322-354`). Prompt-caching markers (`anthropic`/`openrouter` ephemeral cache control, `bedrock` cache points, copilot/alibaba variants) are applied to the first two system messages and last two non-system messages for Anthropic-flavored models (`transform.ts:359-408`, `transform.ts:466-485`). `variants()` computes reasoning-effort variants ("low"/"medium"/"high"/"xhigh"/"max" families) per SDK package and model family (`transform.ts:727-1155`); `options()` sets request defaults such as `store: false` for OpenAI-family SDKs and `reasoningEffort: "medium"` for gpt-5 (`transform.ts:1157-1325`); `maxOutputTokens` is `min(model.limit.output, 32_000)` with `OUTPUT_TOKEN_MAX = 32_000` (`transform.ts:18`, `transform.ts:1418-1420`).

### Auth storage and flows

Credentials live in `Global.Path.data/auth.json` (`$XDG_DATA_HOME/opencode/auth.json`) (`packages/opencode/src/auth/index.ts:10`, `packages/core/src/global.ts:11`). The `Info` union has three shapes: `oauth` (`refresh`, `access`, `expires`, optional `accountId`, `enterpriseUrl`), `api` (`key`, optional `metadata` string map), `wellknown` (`key`, `token`) (`packages/opencode/src/auth/index.ts:14-36`). `Auth.all` returns `JSON.parse(process.env.OPENCODE_AUTH_CONTENT)` when that variable is set, without schema validation; otherwise it reads the file and filters entries through the union decoder (`packages/opencode/src/auth/index.ts:58-67`). `set`/`remove` normalize trailing `/` on keys and write the file with mode `0o600` (`packages/opencode/src/auth/index.ts:73-89`). `OAUTH_DUMMY_KEY = "opencode-oauth-dummy-key"` is a sentinel for API-key flows that only need a placeholder (`packages/opencode/src/auth/index.ts:8`).

Interactive auth is plugin-driven: `ProviderAuth` collects `auth` hooks from plugins and exposes `methods`/`authorize`/`callback` (`packages/opencode/src/provider/auth.ts:109-128`). Methods are `oauth` or `api` typed with optional text/select prompts (`packages/opencode/src/provider/auth.ts:11-48`). `authorize` runs prompt validation, invokes the plugin's `method.authorize`, stores the pending OAuth exchange in memory, and returns `{url, method: "auto" | "code", instructions}` (`packages/opencode/src/provider/auth.ts:163-186`). `callback` completes the exchange and persists either `{type: "api", key, metadata?}` or `{type: "oauth", access, refresh, expires, ...}` via `Auth.set` (`packages/opencode/src/provider/auth.ts:188-221`). The plugin bundles that implement these flows (openai/, github-copilot/, azure.ts, cloudflare.ts, ...) live under `packages/opencode/src/plugin/` and are covered by the opencodeExtensibility note.

### Environment variable handling

- `Flag` reads `OPENCODE_*` variables; some at module load (`OPENCODE_CONFIG`, `OPENCODE_CONFIG_CONTENT`, `OPENCODE_DISABLE_AUTOCOMPACT`, `OPENCODE_DISABLE_PRUNE`, `OPENCODE_DISABLE_MODELS_FETCH`, `OPENCODE_MODELS_URL`, `OPENCODE_MODELS_PATH`, OTEL vars), others via getters evaluated at access time (`OPENCODE_DISABLE_PROJECT_CONFIG`, `OPENCODE_CONFIG_DIR`, `OPENCODE_PERMISSION`, `OPENCODE_PURE`, `OPENCODE_CLIENT`, `OPENCODE_TUI_CONFIG`, `OPENCODE_PLUGIN_META_FILE`) (`packages/core/src/flag/flag.ts:15-78`). `truthy()` accepts `"true"` or `"1"` (`packages/core/src/flag/flag.ts:3-6`); `OPENCODE_EXPERIMENTAL` gates experimental flags (`packages/core/src/flag/flag.ts:11-13`).
- The `Env` service is a per-instance mutable snapshot `{ ...process.env }` (`packages/opencode/src/env/index.ts:19-37`); `Env.set` mutates only the snapshot, per the TODO comment at `packages/opencode/src/provider/provider.ts:312-313`. Some integrations therefore write `process.env` directly: `OPENCODE_CONSOLE_TOKEN` (`packages/opencode/src/config/config.ts:490-493`), `AWS_BEARER_TOKEN_BEDROCK` (`packages/opencode/src/provider/provider.ts:314-322`), `AICORE_SERVICE_KEY` (`packages/opencode/src/provider/provider.ts:574-582`). ## Relevance to the brief

This note is my inference, separated from code facts.

- RQ1/RQ2 (what makes a harness, and where the three differ): OpenCode's config layer answers the "configuration" dimension with a nine-layer precedence chain that is notably deeper than a typical CLI config: remote org config, global JSONC, an explicit custom file, a walk-up project file, per-directory `.opencode` bundles with markdown agents/commands and auto-installed plugin deps, inline env config, console config, OS managed dirs, and MDM plist. The two genuinely distinctive choices are (a) enterprise-style MDM override at the top ("override everything", `packages/opencode/src/config/config.ts:524`) and (b) config-driven background `npm install` of the plugin SDK into every config directory (`packages/opencode/src/config/config.ts:438-457`), which makes extensibility a config-load side effect. Its provider layer is the strongest contrast with Codex: instead of a `model_providers` table in one TOML file, OpenCode builds providers at runtime from a hosted catalog (`models.opencode.ai`), env detection, stored auth, plugin hooks, and on-demand npm installation of arbitrary AI-SDK packages (`packages/opencode/src/provider/provider.ts:1812-1830`), with 23 hand-written per-provider integrations for auth, endpoints, and quirks.
- RQ3 (capability vs safety): config handling is capability-first. Unknown config keys are ignored rather than rejected, `{env:VAR}` silently falls back to empty, `OPENCODE_AUTH_CONTENT` replaces credentials unvalidated, and any npm package named in `model.api.npm` gets installed and executed (`packages/opencode/src/config/parse.ts:42`, `packages/opencode/src/config/variable.ts:37`, `packages/opencode/src/auth/index.ts:59-63`, `packages/opencode/src/provider/provider.ts:1816-1830`). The only hard constraints are MDM/managed files at the top of precedence and the `enabled_providers`/`disabled_providers` gates. There is no sandboxing at this layer; isolation questions belong to the permissions component.
- RQ4 is not engaged (Claude Code is closed).
- Open questions for synthesis: whether the `.opencode` directory precedence asymmetry (Fact 4) is intentional (it means a repo-root `.opencode` overrides a subdirectory one, while plain `opencode.json` does the reverse); how model selection persists (`model.json` is written elsewhere, `packages/opencode/src/provider/provider.ts:1983` reads it); and how the catalog, plugins, and TUI model picker intersect, which the interfaces note must cover.
