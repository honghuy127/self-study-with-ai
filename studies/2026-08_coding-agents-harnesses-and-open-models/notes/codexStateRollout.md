## Purpose and role in the harness

- Every Codex thread ("conversation") is durably recorded as an append-only JSON Lines rollout file under `codex_home/sessions/YYYY/MM/DD/`, so a session can be replayed, resumed, forked, listed, searched, or inspected after the process exits (`codex-rs/rollout/src/recorder.rs:1-1`, `codex-rs/rollout/src/recorder.rs:1607-1629`, `codex-rs/rollout/src/lib.rs:67-68`).
- Persistence is layered: a `ThreadStore` trait owns the storage boundary, `LiveThread` is the per-active-session handle that applies the persistence policy and metadata sync, and `RolloutRecorder` is the local JSONL writer (`codex-rs/thread-store/README.md:9-30`, `codex-rs/thread-store/src/live_thread.rs:30-42`, `codex-rs/rollout/src/recorder.rs:85-90`).
- On resume, the rollout file is read back, wrapped in `InitialHistory::Resumed`, and replayed through a reverse scan plus forward reconstruction to rebuild the exact model-visible transcript, compaction checkpoints included (`codex-rs/core/src/thread_manager.rs:970-987`, `codex-rs/core/src/session/rollout_reconstruction.rs:114-437`).
- Queryable per-thread metadata is mirrored into a bundle of SQLite databases (state, logs, goals, memories, queue, thread history) with a one-time backfill from the rollout files, so listing and filtering threads does not require scanning every JSONL file (`codex-rs/state/src/sqlite.rs:29-34`, `codex-rs/rollout/src/state_db.rs:45-54`, `codex-rs/rollout/src/metadata.rs:154-377`).
- Long-lived "memories" are derived offline: a two-phase pipeline reads rollouts from the state DB (Phase 1, per-rollout extraction) and consolidates them into filesystem artifacts under `~/.codex/memories/` (Phase 2) (`codex-rs/memories/README.md:31-152`). A separate `~/.codex/history.jsonl` stores raw user/agent message text for the TUI prompt history, independent of rollouts (`codex-rs/message-history/src/lib.rs:1-15`).

## Mechanism

### Rollout file format

- Layout directory: `codex_home/sessions/YYYY/MM/DD/` with date parts taken from the local start time (`codex-rs/rollout/src/recorder.rs:1612-1619`). `SESSIONS_SUBDIR = "sessions"` and `ARCHIVED_SESSIONS_SUBDIR = "archived_sessions"` (`codex-rs/rollout/src/lib.rs:67-68`).
- Filename grammar: `rollout-<timestamp>-<thread-id>.jsonl` where the timestamp uses `[year]-[month]-[day]T[hour]-[minute]-[second]` and the thread id is a UUID. A reverted thread appends a second id: `rollout-<timestamp>-<thread-id>_<rollout-id>.jsonl`, because `thread/revert` keeps the thread ID stable while switching to a new immutable rollout file (`codex-rs/rollout/src/rollout_file_name.rs:39-74`, `codex-rs/rollout/src/recorder.rs:98-104`).
- Each line is a `RolloutLine`: `{"timestamp": ..., "ordinal"?: ..., ...item fields}`. The writer serializes a `RolloutLineRef` with `timestamp: String`, optional `ordinal: Option<u64>`, and `#[serde(flatten)] item` (`codex-rs/history/src/lib.rs:200-207`, `codex-rs/rollout/src/recorder.rs:1939-1946`). Per-line timestamps read `[year]-[month]-[day]T[hour]:[minute]:[second].[subsecond digits:3]Z` in UTC (`codex-rs/rollout/src/recorder.rs:1954-1959`).
- The flattened item is internally tagged: `#[serde(tag = "type", rename_all = "snake_case")]` over nine variants, `session_meta`, `response_item` (with optional sidecar `metadata`), `inter_agent_communication`, `inter_agent_communication_metadata`, `compacted`, `turn_context`, `world_state`, `security_risk_score`, `event_msg` (`codex-rs/history/src/rollout_payload.rs:20-52`, `codex-rs/history/src/lib.rs:94-105`).
- The first record of a rollout is a `SessionMetaLine` ("session_meta"), a flattened `SessionMeta` plus optional `git` info; the git block is collected only when the session cwd is inside a git repository (`codex-rs/rollout/src/recorder.rs:1852-1879`, `codex-rs/protocol/src/protocol.rs:2962-2968`). `SessionMeta` carries `session_id`, `id` (thread id), `forked_from_id`, `parent_thread_id`, `timestamp`, `cwd`, `originator`, `cli_version`, `source`, `thread_source`, agent nickname/role/path, `model_provider`, `base_instructions`, `dynamic_tools`, `selected_capability_roots`, `memory_mode`, `history_mode`, `history_base`, `subagent_history_start_ordinal`, `multi_agent_version`, `context_window` (`codex-rs/protocol/src/protocol.rs:2872-2929`). A legacy reader tolerates missing `session_id` by copying it from `id` at deserialize time (`codex-rs/protocol/src/protocol.rs:2970-2997`).
- `Compacted` records store the compaction `message`, optional `replacement_history` with a positional `replacement_history_metadata` sidecar, MCP resource origins, and context-window identity (`window_number`, `first_window_id`, `previous_window_id`, `window_id`) (`codex-rs/history/src/lib.rs:141-150`, `codex-rs/history/src/rollout_payload.rs:127-145`). Older rollouts stored the numeric window number in `window_id`; an untagged `WindowIdWire` reads both shapes (`codex-rs/history/src/rollout_payload.rs:245-251`).
- Ordinal sequencing has two modes keyed off `SessionMeta.history_mode`: `ThreadHistoryMode::Legacy` (the serde default, no ordinals written) and `ThreadHistoryMode::Paginated` (every line gets a zero-based monotonically increasing `ordinal`) (`codex-rs/protocol/src/protocol.rs:707-714`, `codex-rs/rollout/src/ordinal.rs:23-54`). On reopen, the ordinal state is recovered by reading the first record for the history mode and scanning the last valid record from the end (`codex-rs/rollout/src/ordinal.rs:56-101`); a paginated subagent rollout whose inherited prefix is incomplete is rejected (`codex-rs/rollout/src/ordinal.rs:87-97`).
- Reading tolerates a serde/`arbitrary_precision` buffering bug through a hand-rolled `decode_rollout_line` that pulls `timestamp` and `ordinal` out of the JSON object before deserializing the flattened item (`codex-rs/rollout/src/lib.rs:35-65`).

### Write path

- `RolloutRecorder` is a cloneable handle over an mpsc command channel (capacity 256) and a background Tokio writer task that owns the file (`codex-rs/rollout/src/recorder.rs:85-90`, `codex-rs/rollout/src/recorder.rs:919-947`, `codex-rs/rollout/src/recorder.rs:1820-1850`). Commands are `AddItems`, `Persist`, `Flush`, `Shutdown` (`codex-rs/rollout/src/recorder.rs:124-136`).
- New sessions defer file creation: `RolloutRecorder::new` precomputes the path and `SessionMeta` but sets `deferred_creation: true`; the file is created only on the first `persist()` so empty sessions leave nothing on disk (`codex-rs/rollout/src/recorder.rs:815-818`, `codex-rs/rollout/src/recorder.rs:889-898`, `codex-rs/rollout/src/recorder.rs:1748-1759`). Resumed sessions immediately reopen the existing file for append (`codex-rs/rollout/src/recorder.rs:900-912`).
- Every record write flushes the file (`codex-rs/rollout/src/recorder.rs:1968-1974`), and on reopen the writer appends a newline if the file does not end with one (`codex-rs/rollout/src/recorder.rs:1920-1933`).
- Failure behavior: `write_pending_with_recovery` writes once, and on error drops the file handle, keeps the unwritten item suffix in `pending_items`, and retries once after reopening; items are drained from the queue only after each individual write succeeds, so an interrupted batch is retried in order (`codex-rs/rollout/src/recorder.rs:1702-1727`, `codex-rs/rollout/src/recorder.rs:1788-1817`). Terminal task failure is remembered and surfaced on later API calls (`codex-rs/rollout/src/recorder.rs:138-179`).
- Live sessions append through `LiveThread::append_items`: items are filtered through the persistence policy, appended raw to the store, and observed by a metadata sync helper that emits `update_thread_metadata` patches (`codex-rs/thread-store/src/live_thread.rs:203-255`). The local store routes appends to the live writer's `report_canonical_items` (`codex-rs/thread-store/src/local/live_writer.rs:358`).
- Persistence policy: everything is persisted except transient events. All `ResponseItem` variants persist except `AdditionalTools`, `CompactionTrigger`, and `Other`; all `EventMsg` lifecycle markers persist; legacy UI events (`UserMessage`, `AgentMessage`, `AgentReasoning`, ...) persist only in Legacy history mode, while paginated rollouts instead persist `ItemCompleted` events that carry `TurnItems` (`codex-rs/rollout/src/policy.rs:9-22`, `codex-rs/rollout/src/policy.rs:38-60`, `codex-rs/rollout/src/policy.rs:86-185`).
- Resume reopens the rollout for append by first materializing a compressed file back to plain JSONL if needed, then recovering ordinal state (`codex-rs/rollout/src/recorder.rs:1896-1918`).

### Session reconstruction after restart

1. Resolution: `ThreadManager::resume_thread_from_rollout` computes `InitialHistory` from a rollout path (`codex-rs/core/src/thread_manager.rs:970-987`). It reads through the thread store (`read_thread_by_rollout_path` with `include_archived: true, include_history: true`) and converts the stored thread into `InitialHistory::Resumed`, erroring fatally if the stored thread lacks persisted history (`codex-rs/core/src/thread_manager.rs:1175-1191`, `codex-rs/core/src/thread_manager.rs:1998-2013`).
2. Path resolution for a thread id is live-writer first, then the SQLite selected rollout path, then filesystem scan, then archived scan (`codex-rs/thread-store/src/local/thread_rollout_resolver.rs:67-147`). After `thread/revert` the SQLite path is authoritative for paginated threads; filesystem fallback is allowed only when SQLite has no row or marks the thread legacy (`codex-rs/thread-store/src/local/thread_rollout_resolver.rs:87-118`).
3. Loading: `RolloutRecorder::load_rollout_items` streams lines via a reader that transparently handles `.jsonl` and `.jsonl.zst`, skips blank lines, counts unparseable lines without failing, strips legacy `ghost_snapshot` items, rejects an unknown `history_mode` in the first `session_meta`, and takes the first `SessionMeta` as the canonical thread id (`codex-rs/rollout/src/recorder.rs:1009-1072`). An entirely empty file is an error ("empty session file") (`codex-rs/rollout/src/recorder.rs:1061-1063`). `get_rollout_history` wraps this as `InitialHistory::New` or `InitialHistory::Resumed` (`codex-rs/rollout/src/recorder.rs:1074-1089`).
4. Spawn: `resume_thread_with_history` restores the resumed session/thread source and, for V2 multi-agent root threads, restores sub-agent metadata before spawning (`codex-rs/core/src/thread_manager.rs:989-1024`). Session creation calls `sess.record_initial_history(initial_history)` after `SessionConfigured` is emitted, and reports `SessionStartSource::Resume` for hooks (`codex-rs/core/src/session/session.rs:1470-1479`, `codex-rs/core/src/session/session.rs:1471`).
5. Reconstruction: `record_initial_history` for `Resumed` detects an interrupted trailing turn, calls `apply_rollout_reconstruction`, then `reconstruct_history_from_rollout` (`codex-rs/core/src/session/mod.rs:1353-1401`, `codex-rs/core/src/session/rollout_reconstruction.rs:114-437`). The core pass scans records newest-to-oldest, finalizing per-turn segments at `TurnStarted`, until it has both a surviving compaction `replacement_history` base and the resume metadata (previous settings, reference context item); it then replays only the surviving suffix forward (`codex-rs/core/src/session/rollout_reconstruction.rs:155-298`, `codex-rs/core/src/session/rollout_reconstruction.rs:328-378`). A `Compacted` checkpoint with `replacement_history` is a complete history base that discards older records (`codex-rs/core/src/session/rollout_reconstruction.rs:344-348`). `ThreadRolledBack` events drop the newest N user turns in both passes (`codex-rs/core/src/session/rollout_reconstruction.rs:189-192`, `codex-rs/core/src/session/rollout_reconstruction.rs:369-371`). World-state full snapshots and merge patches are replayed chronologically to restore the baseline (`codex-rs/core/src/session/rollout_reconstruction.rs:392-419`). The rebuilt history, previous turn settings, reference context item, world-state baseline, and context-window ids are installed into session state (`codex-rs/core/src/session/mod.rs:1466-1520`).
6. On resume Codex seeds token usage from the newest recorded `TokenCount` event for immediate UI display and warns (via an event) when the recorded model differs from the current one (`codex-rs/core/src/session/mod.rs:1369-1394`, `codex-rs/core/src/session/mod.rs:1554-1559`).

### SQLite state databases

- The state runtime owns six SQLite files in the sqlite home: `state_5.sqlite`, `logs_2.sqlite`, `goals_1.sqlite`, `memories_1.sqlite`, `queue_1.sqlite`, `thread_history_1.sqlite` (`codex-rs/state/src/sqlite.rs:29-34`). All pools open WAL with `SYNCHRONOUS=NORMAL`, incremental auto-vacuum, a 5-second busy timeout, and up to 5 connections (`codex-rs/state/src/sqlite.rs:278-291`). The crate statically asserts bundled SQLite >= 3.51.3 for a WAL-reset corruption fix (`codex-rs/state/src/lib.rs:7-10`).
- The sqlite home defaults under the codex home and is overridden by `CODEX_SQLITE_HOME` (`codex-rs/state/src/lib.rs:103`, `codex-rs/core/src/config/mod.rs:229`).
- Schema is driven by 49 numbered migrations in `codex-rs/state/migrations/` (`0001_threads.sql` through `0049_projects.sql`); the base `threads` table stores `id`, `rollout_path`, timestamps, `source`, `model_provider`, `cwd`, `title`, `sandbox_policy`, `approval_mode`, token usage, archive flags, and git identity (`codex-rs/state/migrations/0001_threads.sql:1-19`). Later migrations add CLI version, first user message, backfill state, recency, history mode, explicit title, section/pinning, and projects.
- Initialization runs a backfill gate: `init` opens the runtime, then waits for (or performs) the rollout-to-SQLite backfill to complete, polling every 1 second with a 30-second timeout before failing startup initialization (`codex-rs/rollout/src/state_db.rs:95-128`, `codex-rs/rollout/src/state_db.rs:130-192`). The bridge `init_state_db` is the core entry point (`codex-rs/core/src/state_db_bridge.rs:6-8`) and is invoked at startup by exec, the MCP server, the app-server client, and the TUI (`codex-rs/exec/src/lib.rs:527`, `codex-rs/mcp-server/src/lib.rs:100`, `codex-rs/app-server-client/src/lib.rs:845`, `codex-rs/tui/src/lib.rs:526`).
- Backfill scans the sessions and archived directories in batches of 200, extracts metadata from each rollout, upserts `threads` rows, claims a lease (`BACKFILL_LEASE_SECONDS = 900`, `BACKFILL_BATCH_SIZE = 200`), checkpoints a watermark, and records success/failure metrics (`codex-rs/rollout/src/metadata.rs:32-36`, `codex-rs/rollout/src/metadata.rs:154-377`). Metadata extraction derives defaults from `SessionMeta` (sandbox policy seeded read-only, approval mode `OnRequest`) and then folds each rollout item through `apply_rollout_item` (`codex-rs/rollout/src/metadata.rs:38-64`, `codex-rs/rollout/src/metadata.rs:111-152`).
- Listing is SQLite-first with filesystem fallback and repair: `list_threads_with_db_fallback` over-fetches a filesystem page, read-repairs or reconciles each hit into SQLite, then returns the DB page (or the filesystem page when the DB is unavailable, recording a fallback reason) (`codex-rs/rollout/src/recorder.rs:459-729`). `get_state_db` opens the DB only when it exists and its backfill already completed, for non-owning contexts (`codex-rs/rollout/src/state_db.rs:208-277`).

### Discovery, listing, search

- Thread listing pages over rollout files (or the state DB), supports `CreatedAt`/`UpdatedAt`/`RecencyAt` sort keys and asc/desc direction, and filters by source, model provider, cwd, and search term (`codex-rs/rollout/src/recorder.rs:328-360`, `codex-rs/rollout/src/list.rs:129-129`). Head reads for listing summaries cap at `HEAD_RECORD_LIMIT = 10` records with a `USER_EVENT_SCAN_LIMIT = 200` (`codex-rs/rollout/src/list.rs:125-126`).
- Finding a thread by id uses the state DB first, then scans `sessions/` (and `archived_sessions/` when archived ids are requested) by matching the canonical filename (`codex-rs/rollout/src/list.rs:1580-1594`, `codex-rs/thread-store/src/local/thread_rollout_resolver.rs:119-147`). Finding the newest thread (for `resume` with no id) pages through the DB or file listing, optionally matching cwd against the recorded or latest `TurnContext` cwd (`codex-rs/rollout/src/recorder.rs:731-813`, `codex-rs/rollout/src/recorder.rs:2058-2087`).
- Thread display names live in a sidecar append-only index `session_index.jsonl` in the codex home, one `SessionIndexEntry {id, thread_name, updated_at}` per line, newest entry wins, resolved by scanning from the end (`codex-rs/rollout/src/session_index.rs:21-29`, `codex-rs/rollout/src/session_index.rs:31-50`, `codex-rs/rollout/src/session_index.rs:264-296`). Content search across rollouts shells out to `rg` with per-match context windows (`codex-rs/rollout/src/search.rs:23-24`, `codex-rs/rollout/src/search.rs:29-50`).
- Cold rollouts are compressed to `<name>.jsonl.zst` by a background worker (zstd level 3, files older than 7 days), throttled by a run marker and bounded to a 5-hour runtime; referenced rollouts and fork-pointer rollouts (`history_base` set) are skipped, and appends transparently decompress the file back to plain JSONL (`codex-rs/rollout/src/compression.rs:254-261`, `codex-rs/rollout/src/compression.rs:632-701`, `codex-rs/rollout/src/compression.rs:504-513`, `codex-rs/rollout/src/compression.rs:73-123`). Compression and legacy migration share a nonblocking `rollout-maintenance.lock` per codex home (`codex-rs/rollout/src/maintenance.rs:16-40`).

### Message history and memories

- `~/.codex/history.jsonl` stores prompt-history records `{"session_id","ts","text"}` with single `write(2)` appends under `O_APPEND` for atomicity and an advisory lock with retries (`codex-rs/message-history/src/lib.rs:1-15`, `codex-rs/message-history/src/lib.rs:61-66`). Persistence defaults to `save-all` and is configurable to `none`; an optional `max_bytes` trims oldest entries down to 80% of the cap (`codex-rs/config/defaults.toml:16-17`, `codex-rs/config/src/types.rs:205-213`, `codex-rs/message-history/src/lib.rs:55-56`, `codex-rs/message-history/src/lib.rs:195-240`).
- The memory system splits read and write crates. Read owns injection root resolution (`codex_home/memories`), citation parsing, and usage telemetry (`codex-rs/memories/read/src/lib.rs:13-15`). Write owns the startup pipeline, artifacts, Phase 1/2 prompt rendering, and workspace diffing; artifact names are `raw_memories.md`, `rollout_summaries/`, `extensions/` with a 7-day extension-retention window (`codex-rs/memories/write/src/lib.rs:35-44`). The pipeline runs at root-session startup only when the session is not ephemeral, memory is enabled, it is not a sub-agent, and the state DB is available (`codex-rs/memories/README.md:31-38`). `generate_memories` defaults to true and is recorded in `SessionMeta.memory_mode` as `"disabled"` when off (`codex-rs/config/src/types.rs:343`, `codex-rs/rollout/src/recorder.rs:881`).

### Rollout tracing and agent graph

- `codex-rollout-trace` is an opt-in diagnostic trace bundle written next to rollouts, enabled by the `CODEX_ROLLOUT_TRACE_ROOT` env var, with a reduced `state.json` produced by replay (`codex-rs/rollout-trace/src/thread.rs:44`, `codex-rs/rollout-trace/src/bundle.rs:12`, `codex-rs/rollout-trace/src/lib.rs:24-78`). On resume, child-trace derivation is disabled to avoid re-emitting `ThreadStarted` and breaking replayability (`codex-rs/core/src/thread_manager.rs:1967-1995`).
- `codex-agent-graph-store` tracks the parent/child spawn topology of threads as storage-neutral edges (`codex-rs/agent-graph-store/src/lib.rs:1-13`).

## Key facts with anchors

- Rollout files are JSONL under `sessions/YYYY/MM/DD/`, named `rollout-<ts>-<thread-id>.jsonl` (reverted threads `..._<rollout-id>.jsonl`); first line is a `session_meta` record (`codex-rs/rollout/src/recorder.rs:1607-1629`, `codex-rs/rollout/src/rollout_file_name.rs:39-74`, `codex-rs/rollout/src/recorder.rs:1852-1879`).
- Each line is `{timestamp, ordinal?, ...item}` with the item internally tagged by `type` (`codex-rs/rollout/src/recorder.rs:1939-1946`, `codex-rs/history/src/rollout_payload.rs:20-52`).
- Writes flush per record, creation is deferred until first persist, and failed writes retry once with the pending items retained (`codex-rs/rollout/src/recorder.rs:1968-1974`, `codex-rs/rollout/src/recorder.rs:815-818`, `codex-rs/rollout/src/recorder.rs:1702-1727`).
- The persistence policy drops only a small set of transient items; mode-dependent behavior splits Legacy vs Paginated event persistence (`codex-rs/rollout/src/policy.rs:38-60`, `codex-rs/rollout/src/policy.rs:86-185`).
- Resume resolves the rollout path (live writer, SQLite, filesystem, archived), loads items tolerantly, and returns `InitialHistory::Resumed` (`codex-rs/thread-store/src/local/thread_rollout_resolver.rs:67-147`, `codex-rs/rollout/src/recorder.rs:1009-1089`, `codex-rs/core/src/thread_manager.rs:1998-2013`).
- Transcript reconstruction is a reverse scan for a compaction base plus a forward replay, honoring `ThreadRolledBack` and restoring world-state baselines and context-window ids (`codex-rs/core/src/session/rollout_reconstruction.rs:114-437`).
- Thread metadata is mirrored into six SQLite DBs (e.g. `state_5.sqlite`) opened WAL with a 5s busy timeout, seeded by a leased backfill with a 30s startup gate (`codex-rs/state/src/sqlite.rs:29-34`, `codex-rs/state/src/sqlite.rs:278-291`, `codex-rs/rollout/src/state_db.rs:130-192`, `codex-rs/rollout/src/metadata.rs:154-377`).
- Listing prefers SQLite with filesystem read-repair fallback; cold rollouts compress to `.jsonl.zst` (`codex-rs/rollout/src/recorder.rs:459-729`, `codex-rs/rollout/src/compression.rs:632-701`).
- A sidecar `session_index.jsonl` stores thread display names newest-wins; raw message text lives separately in `~/.codex/history.jsonl` (`codex-rs/rollout/src/session_index.rs:21-29`, `codex-rs/message-history/src/lib.rs:1-66`).
- Memories are generated offline from rollouts into `~/.codex/memories/` artifacts by a two-phase pipeline (`codex-rs/memories/README.md:40-152`, `codex-rs/memories/write/src/lib.rs:35-44`).

## Configuration and defaults

- Session storage roots: `sessions` and `archived_sessions` under the codex home (`codex-rs/rollout/src/lib.rs:67-68`). The codex home itself is configured elsewhere (config/providers dimension); rollout code consumes it via `RolloutConfigView::codex_home` (`codex-rs/rollout/src/config.rs:6-12`).
- SQLite: filename constants `state_5.sqlite`, `logs_2.sqlite`, `goals_1.sqlite`, `memories_1.sqlite`, `queue_1.sqlite`, `thread_history_1.sqlite` (`codex-rs/state/src/sqlite.rs:29-34`); override env `CODEX_SQLITE_HOME` (`codex-rs/state/src/lib.rs:103`); pool WAL/normal-sync/incremental-autovacuum/5s busy/5 conns (`codex-rs/state/src/sqlite.rs:278-291`); `MAX_QUEUE_ITEMS = 100` (`codex-rs/state/src/lib.rs:94`); pinned section id `01984de2-8f74-7c91-a3b2-5c5e937cf318`, name "Pinned" (`codex-rs/state/src/lib.rs:96-100`). The sqlite default *location* when `CODEX_SQLITE_HOME` is unset is set by the config layer, not this crate, so I mark the exact default path `[EVIDENCE NEEDED]` (I checked `codex-rs/state/src/sqlite.rs` and `codex-rs/core/src/config/mod.rs:229` but did not trace the unset fallback).
